# 言語の全体像

## 処理モデル

SakuraMML はソースを先頭から読み、現在のトラックに対する状態変更と MIDI イベントの追加を行う言語です。
処理は概念上、次の順序です。

1. 入力バイト列を UTF-8 または CP932 として読み取る。
2. 全角記号を構文用の半角記号へ正規化する。
3. ストトン表記と利用者定義の日本語マクロを通常 MML へ展開する。
4. コマンド、音符、式、ブロックを解釈し、トラック別の絶対時刻イベントを作る。
5. イベントを時刻順に並べ、Standard MIDI File として直列化する。

文字列リテラルの中身は 2 と 3 の置換対象になりません。

## 文字と大文字・小文字

現行 Rust の内部文字列は UTF-8 です。構文上の基本記号と数値は ASCII を使用します。
全角 ASCII、全角空白、`♯`、`♭`、`【】`、`↑↓`、一部の漢数字は前処理で対応する半角文字に変換されます。

コマンド名の大文字・小文字は一律には無視されません。明示された別名だけが有効です。
たとえば `Tempo`、`TEMPO` は有効ですが、任意の `tempo` を受理するとは限りません。
移植可能な曲では本書に記載した綴りを使用してください。

## 区切りとコメント

空白、タブ、改行、`;` は通常、コマンド間の区切りです。

```mml
Tempo=120; o5 l8; c d e f
```

コメントは次の形式を使用できます。

```mml
// 行末までのコメント
/* 複数行にまたがるコメント */
```

コメントや区切りは、文字列および対応するブロック内部のデータを壊してはいけません。

## 数値

整数は 10 進数で記述します。負号を使用できます。`$` を先頭に付けると 16 進数です。

```mml
v100
Key=-2
SysEx($F0,$7E,$7F,$09,$01,$F7)
```

現行 Rust の式は符号付き 64 bit 整数で評価され、加減乗除などのオーバーフローはエラーになります。
MIDI に 7 bit 値を書き込む一部のコマンドは、最終的な値を 0〜127 に丸めます。

## 文字列と配列

文字列は二重引用符で囲みます。メタイベントでは、従来互換の `{"..."}` が基本形です。

```mml
Str title={"春"}
TrackName=title
Array chord=(60,64,67)
```

配列の添字は 0 から始まります。範囲外の参照はコンパイルエラーです。

## 引数の三つの形

SakuraMML には歴史的に複数の引数形式があります。

| 形式 | 例 | 式の扱い |
|---|---|---|
| 直結 | `v100`, `o5`, `l8` | 原則として整数または音長 |
| 括弧 | `Tempo(60+60)`, `o(x)` | 括弧内で式を評価 |
| 代入形 | `Tempo=120`, `Voice=instrument` | 右辺は単一の値・変数・関数呼び出し |

`Tempo=100+20` のような複合式は使用せず、`Tempo(100+20)` と書きます。
単文字属性も、変数を使う場合は `o(x)` のように括弧で囲みます。

## ブロック

`{ ... }` は制御構文、マクロ、`Sub`、`Div` などの本体を表します。
`[ ... ]` は MML 固有の反復です。`' ... '` は和音です。
開始記号と終了記号が対応しない場合は、行番号付きのエラーになります。

## 既定値

| 状態 | 初期値 |
|---|---:|
| 現在トラック | 1 |
| タイムベース | 四分音符 96 tick |
| 拍子 | 4/4 |
| オクターブ | 5 |
| 既定音長 | `l4` = 96 tick |
| ベロシティ | 100 |
| ゲート | 80 |
| 発音タイミング補正 | 0 tick |
| `System.qMax` | 100 |
| `System.vMax` | 127 |
| キーシフト | 0 |
